## Запуск интерфейса и API

Готовый HTTPS-стенд с Supabase запускается из корня одной командой в PowerShell 7.4+:

```powershell
.\scripts\start-stand.ps1
```

Скрипт использует существующие `.venv` и `backend/.env`. Когда `/health` вернёт `ready`, он открывает приложение в браузере по умолчанию и печатает путь к логу для `trace_id`. [Подробности запуска](docs/deployment.md#запуск-локального-стенда-одной-командой).

На Windows x64 используйте **Python 3.12.10**, **Node.js 24.11.0** и **npm 11.6.1**. Корневой [requirements.txt](requirements.txt) фиксирует версии из рабочего Python-окружения, а [package-lock.json](frontend/package-lock.json) используется через `npm ci`.

Если `.venv` ещё нет, создайте её из корня проекта:

```powershell
py -3.12 -m venv .venv
```

Установите зависимости из корня проекта. Команда ниже подходит для локальной работы с SQLite без входа. Для входа через Supabase запустите HTTPS-стенд выше или используйте [команду запуска с `backend/.env`](docs/supabase-migration.md#запуск-с-supabase).

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

Во втором терминале из корня проекта установите зависимости по lock-файлу и запустите Vite. При повторном запуске достаточно `npm run dev` из `frontend`.

```powershell
cd frontend
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173. В разделе «Документы» доступны поиск и чтение. Ссылка «Задать вопрос по документу» открывает форму с названием выбранного документа. В истории видны вопросы и статусы. UUID открывается в «Деталях заявки». Браузер хранит номера заявок и перечитывает данные с сервера.

Адрес API задаётся в `frontend/src/config.ts` значением по умолчанию http://127.0.0.1:8000 или переменной `VITE_API_BASE_URL` в `frontend/.env.local`. Пример:

```powershell
Copy-Item frontend/.env.example frontend/.env.local
```

После изменения переменных Vite перезапустите dev-сервер. Порт интерфейса фиксирован: 5173, автоматического перехода на другой порт нет. FastAPI разрешает CORS только для http://127.0.0.1:5173; http://localhost:5173 считается другим origin. Оба сервера слушают loopback, публичный доступ не настроен.

Чтобы применить `backend/.env`, добавьте к команде запуска `--env-file backend/.env`. Для PostgreSQL на Windows также укажите `--loop backend.app.postgres:selector_loop`. Проверка готовности доступна по `GET /health`. Для локального поиска сначала соберите индекс командой `.\.venv\Scripts\python.exe -X utf8 ingest.py`.

Для проверки сборки из frontend:

```powershell
npm run build
npm run lint
```

Локальный просмотр сборки: остановите Vite dev и выполните `npm run preview`; он использует тот же адрес 127.0.0.1:5173 и разрешённый CORS origin.

## API

API реализован на FastAPI; документы и заявки сохраняются в файле базы и доступны после перезапуска с прежними `id` и содержимым.

Для запуска используйте команду из корня проекта в разделе «Запуск интерфейса и API» выше. Не запускайте второй экземпляр, пока порт `8000` уже используется. Интерактивная документация доступна по адресу `http://127.0.0.1:8000/docs`.

| Метод | Путь | Действие |
|---|---|---|
| GET | `/health` | Проверить готовность базы и индекса |
| GET | `/documents` | Получить все документы |
| POST | `/documents` | Создать документ |
| POST | `/documents/upload?filename=...` | Загрузить файл и сразу добавить в поисковый индекс |
| GET | `/documents/{id}` | Получить документ |
| PATCH | `/documents/{id}` | Обновить непустые поля документа |
| DELETE | `/documents/{id}` | Удалить документ |
| POST | `/requests` | Создать заявку |
| GET | `/requests/{id}` | Получить заявку |
| PATCH | `/requests/{id}` | Изменить статус заявки |
| POST | `/requests/{id}/replies` | Сохранить ответ и закрыть заявку |
| PATCH | `/requests/{id}/replies/{reply_id}` | Отредактировать ответ |
| DELETE | `/requests/{id}/replies/{reply_id}` | Удалить ответ из истории |
| POST | `/ai/summary` | Подготовить резюме вопроса для проверки человеком |
| POST | `/ai/tools` | Предложить и выполнить проверенный поиск или показать черновик заявки |
| POST | `/consultations` | Сохранить черновик консультации для подтверждения |
| GET | `/requests/{id}/delivery` | Прочитать состояние тестовой доставки и квитанцию своей заявки |
| POST | `/requests/{id}/delivery/retry` | Повторить доставку `unknown` в тот же workflow v2 |
| POST | `/ask` | Найти ответ по локальному корпусу с цитатами |
| GET | `/ask/sources/{chunk_id}` | Открыть документ и точный процитированный фрагмент |

У документа обязательны непустые строковые `title`, `text`, `source`; у заявки — `name` и `question`. Сервер назначает каждой записи `id`; заявке также назначается `status: "new"`.

В «Заявках» используйте **«Взять в работу»**, **«Закрыть заявку»** или **«Возобновить»**. Статус сохраняется в SQLite. API принимает текущий статус в `expected_status` и следующий в `status`. Допустимы переходы `new → in_progress → resolved` и `resolved → in_progress`.

Откройте заявку в истории, чтобы написать ответ. Действие **«Ответить и закрыть»** сохраняет запись в ленте активности и закрывает заявку одной транзакцией. После возобновления можно отправить следующий ответ. Маршрут принимает UUID ответа в `id` и текст в `text`. Повтор с тем же UUID и текстом возвращает уже сохранённый ответ в истории.

Поиск в истории проверяет вопросы и ответы с учётом выбранного статуса. У сегодняшних заявок в списке видно время, у остальных дату с годом. Точное время доступно при наведении. Прочерк означает, что заявка была создана до записи даты отправки. Меню **«…»** в ленте активности позволяет отредактировать ответ на месте или удалить его после подтверждения.

## Справка с места работы

Пилот справок включается на защищённом стенде с тестовыми аккаунтами. Используйте вымышленные кадровые данные.

1. На тестовом PostgreSQL примените [миграцию справок](supabase/migrations/20261121131406_employment_certificates.sql). В SQLite таблица создаётся при старте.
2. Скопируйте [пример реестра](data/certificate-registry.example.json) в приватный файл за пределами репозитория. В `employees` укажите UUID тестового сотрудника. Кадровику дайте доступ к очереди и [отдельный допуск к выдаче](docs/supabase-migration.md#управление-пользователями-в-приложении). Для прежней настройки через реестр используйте `issuer_ids`. Оба аккаунта должны быть зарегистрированы в `knowledge_desk.members`.
3. Задайте абсолютный путь к этому JSON в `KNOWLEDGE_DESK_TEST_CERTIFICATE_REGISTRY` в серверном `backend/.env` и запустите стенд. После изменения реестра перезапустите сервер.
4. Под сотрудником откройте **«Заявки» → «Запросить справку»**. Под кадровиком откройте новую заявку, нажмите **«Скачать черновик (Word)»**, затем прикрепите подписанный PDF до 5 МиБ и нажмите **«Выдать справку»**. Сотрудник скачивает PDF из той же карточки после обновления.

Черновик формируется из [DOCX-шаблона](backend/app/templates/employment-certificate.docx) и записи реестра. Подпись ставит кадровик средствами организации. Приложение проверяет читаемость PDF и право выдачи. Файлы и запись о выдаче хранятся в закрытой таблице; запись и закрытие заявки выполняются вместе. Справки исключены из индекса поиска.

При подключённом n8n после выдачи сотрудник получает письмо со ссылкой на свою заявку. [Подключение уведомлений](docs/n8n-delivery.md#справка-готова)

## Резюме заявки

Провайдер OpenAI, модель `gpt-4.1-mini`, Python SDK `openai==2.26.0`. Перед запуском FastAPI задайте `OPENAI_API_KEY` в окружении серверного процесса. Без ключа `/ai/summary` и `/ask`, если вопрос требует генерации, возвращают `503`. Поиск, выдача источников и работа каталога доступны без ключа. Параметры Vite предназначены для публичной конфигурации браузера.

Откройте «Заявки», введите вымышленный вопрос и нажмите «Подготовить резюме». Браузер передаст серверу только текст вопроса. Предложение появится в форме для ручной проверки. Для проверки через Swagger выполните `POST /ai/summary` с телом `{"text":"Есть ли в вымышленном курсе «Орбита» модуль по тестированию Python?"}`. Пример ответа:

```json
{
  "summary": "Запрос о наличии модуля по тестированию Python в курсе «Орбита».",
  "request_type": "course_question",
  "needs_human": false
}
```

Сервер принимает до 4000 символов, ждёт модель до 15 секунд и ограничивает ответ 256 токенами. На один процесс FastAPI выделено пять попыток, включая неудачные, без автоматических повторов. После исчерпания лимита маршрут отвечает `429` с кодом `local_limit`. Перезапуск сбрасывает счётчик. Для общего денежного лимита используйте отдельный проект OpenAI с небольшим бюджетом и включённым принудительным ограничением в настройках владельца.

Превышение длины возвращает `422` с `string_too_long`. Для ошибок модели маршрут возвращает `detail.code` и `detail.message`. Коды `provider_timeout` (`504`), `provider_rate_limit` (`429`), `provider_unavailable`, `provider_refused` и `invalid_summary` (`502`) различают сбои. Форма сохраняет вопрос и предлагает повторить запрос вручную. [Результаты сравнения инструкций](docs/prompt-comparison.md).

Резюме не пишет в SQLite и не отправляет заявку. Тесты `backend/tests/test_summary.py` используют фиксированный ответ SDK.

## Учебный корпус и локальный поиск

Для повседневной загрузки откройте [«Документы»](http://127.0.0.1:5173/#documents) и нажмите **«Загрузить файл»**. PDF и Word (`.docx`) принимаются до 10 МиБ, а `.txt` и `.md` в UTF‑8 до 64 КиБ. Для PDF действует лимит в 150 страниц, для извлечённого текста — 256 КиБ. Сервер сохраняет документ в каталоге после построения поискового индекса. После подтверждения файл доступен в списке, поиске по тексту и «Ответах». Повторная загрузка файла с тем же именем и текстом возвращает существующий документ.

PDF можно загрузить со сканами. Для страниц без текстового слоя сервер запускает локальное распознавание кириллицы через RapidOCR. Модель скачивается при первом распознавании и дальше используется из кэша. На файл допускается до 20 страниц, требующих распознавания. Для PDF с паролем сохраните разблокированную копию. Старый Word (`.doc`) можно пересохранить как `.docx`. Из Word читаются абзацы и строки таблиц основного текста.

Для PDF приложение сохраняет оригинал в SQLite и привязывает каждый фрагмент к физической странице файла, считая с первой. В «Ответах» выберите источник, чтобы открыть нужную страницу справа от ответа. Ссылка под цитатой открывает оригинал в новой вкладке. Ранее загруженные PDF загрузите повторно, чтобы сохранить оригинал и добавить номера страниц. Если изменить извлечённый текст в редакторе, для этой версии будут доступны текстовые цитаты без номера страницы. Распознавание зависит от чёткости скана. Важные суммы, даты и номера сверяйте с оригиналом.

При загрузке текст обрабатывается локальной моделью эмбеддингов. OpenAI получает вопрос и выбранные отрывки только при запросе ответа. В режиме Supabase оригиналы PDF и сканов хранятся в приватном Storage, каталог и фрагменты — в PostgreSQL. В режиме SQLite индекс загрузок хранится в соседней папке `.chroma`. [Перенос и проверка PDF](docs/supabase-migration.md#приватное-хранилище-pdf)

Откройте документ и нажмите **«Редактировать»**, чтобы изменить название, источник или текст. После сохранения «Ответы» используют новую версию проиндексированного документа. **«Удалить»** убирает документ из каталога и поиска после подтверждения. Для документов из манифеста эти действия меняют версию, доступную приложению. Исходные файлы на диске сохраняются.

Чтобы подключить другой набор текстов, используйте [настройку своей базы](docs/custom-corpus.md). Выбор корпуса не требует изменений в коде.

В [манифесте](data/manifest.json) перечислены 20 вымышленных [документов «Орбиты»](data/documents/). Для загрузки в каталог интерфейса запустите FastAPI и выполните `.\.venv\Scripts\python.exe -X utf8 import_corpus.py` из корня проекта. Скрипт сопоставляет записи по пути источника и сохраняет UUID существующих документов.

Для Supabase выберите импортированный профиль через `KNOWLEDGE_DESK_CHUNK_SIZE`. Профиль по умолчанию — **400/50**. В режиме SQLite для эксперимента **600/50** соберите индекс командой ниже. Первая загрузка E5 требует интернета.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-rag.txt
.\.venv\Scripts\python.exe -X utf8 ingest.py --chunk-size 600 --index data/orbita-600-v1.chroma
```

Остановите прежний FastAPI. В терминале для сервера задайте путь и размер вместе и повторите запуск. `OPENAI_API_KEY` используется только из окружения этого процесса.

```powershell
$env:KNOWLEDGE_DESK_INDEX = 'data/orbita-600-v1.chroma'
$env:KNOWLEDGE_DESK_CHUNK_SIZE = '600'
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

В [«Ответах»](http://127.0.0.1:5173/#ask) спросите про условия выдачи сертификата и откройте источник под ответом. Для запуска со SQLite индекс по умолчанию берётся из `data/chroma`. Подробнее про [индексацию и переключение](docs/chunking-experiment.md#воспроизведение-и-ручное-переключение), [оценку на 50 вопросах](docs/rag-evaluation-50.md) и [известные ограничения](docs/rag-limitations.md).

## Обновление данных и Redis

Открытый экран в простое не опрашивает API. При возврате в раздел или на вкладку интерфейс сразу показывает сохранённые данные и один раз перепроверяет их, если каталог, документ или источник загружены более 5 минут назад либо список, карточка заявки или доставка загружены более минуты назад. Срок относится к проверке свежести. Кнопка обновления запрашивает данные сразу. Собственные изменения обновляют связанные данные после ответа сервера. Перезагрузка страницы и выход из аккаунта очищают кэш вкладки. Черновики оператора загружаются из Supabase при открытии переписки.

Redis можно включить локально в Docker, указав адрес в серверном `backend/.env` и перезапустив API:

```powershell
docker run -d --name knowledge-desk-redis -p 127.0.0.1:6379:6379 redis:8 redis-server --maxmemory 64mb --maxmemory-policy allkeys-lru
```

```dotenv
KNOWLEDGE_DESK_REDIS_URL=redis://127.0.0.1:6379/0
```

Redis хранит вектор вопроса по хэшу запроса и пользователя до 10 минут. Каждый поиск по-прежнему проверяет актуальные права и читает из индекса. При недоступности Redis сервер вычисляет вектор напрямую. Пустой `KNOWLEDGE_DESK_REDIS_URL` выключает Redis.

## Помощник

В «Ответах» откройте **«Помощник»**. Он может найти до пяти фрагментов по запросу или показать черновик заявки с именем и вопросом. Отправка заявки остаётся отдельным действием пользователя в разделе «Заявки». Оба инструмента работают с настроенной серверной моделью. [Схемы, ограничения и проверка без платной модели](docs/tool-assistant.md).

В помощнике откройте **«Заявка на консультацию»** для сценария LangGraph. Он использует тот же поиск по доступным документам и сохраняет черновик перед показом. Подтверждение конкретной версии записывает одну заявку, повтор возвращает тот же ID. [Сценарий, сохранение и проверки](docs/consultation-workflow.md).

После подтверждения консультации тестовый webhook может получить событие `request.created`. Workflow v2 хранит квитанции в Supabase по `event_id`. Если ответ потерялся, кнопка «Повторить доставку» запрашивает исходную квитанцию с тем же ID. «Новый разговор» очищает диалог, сохраняя заявки и квитанции. [Настройка n8n и проверка повтора](docs/n8n-delivery.md).

## База данных

По умолчанию база находится в `data/knowledge_desk.sqlite3` относительно корня проекта, независимо от папки запуска сервера. При первом запуске автоматически создаются каталог, файл базы и таблицы `documents` и `requests`. Повторный запуск сохраняет существующие записи. У обеих таблиц первичный ключ — строковый UUID в поле `id`.

Все операции с SQLite вынесены в `backend/app/database.py`. Пользовательские значения, включая `id`, передаются параметрами `?`; запись фиксируется транзакцией, при ошибке выполняется откат. Неизвестный `id` возвращает `404`. Неожиданная ошибка возвращает `500` с общим сообщением, а подробности и трассировка попадают в журнал сервера (stderr).

Другой файл можно задать переменной окружения `KNOWLEDGE_DESK_DB_PATH`. Относительный путь в этой переменной считается от текущей рабочей папки; для однозначности используйте абсолютный путь.

### Пустая тестовая база

Из корня проекта в PowerShell укажите новый, ещё не существующий файл и запустите сервер:

```powershell
$env:KNOWLEDGE_DESK_DB_PATH = Join-Path (Get-Location) 'data/test.sqlite3'
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

Сервер создаст пустую базу автоматически. Если `test.sqlite3` уже существует, он откроет её с прежними данными; для чистого запуска выберите новое имя или сохраните копию и удалите старый файл по инструкции ниже. Чтобы вернуться к основной базе после остановки сервера:

```powershell
Remove-Item Env:KNOWLEDGE_DESK_DB_PATH
```

### Сохранение учебных данных перед очисткой

Остановите все процессы сервера, использующие базу (`Ctrl+C`), чтобы во время копирования не было записей. Из корня проекта выполните:

```powershell
$databasePath = if ($env:KNOWLEDGE_DESK_DB_PATH) { $env:KNOWLEDGE_DESK_DB_PATH } else { Join-Path (Get-Location) 'data/knowledge_desk.sqlite3' }
$backupPath = "$databasePath.$(Get-Date -Format 'yyyyMMdd-HHmmss-fff').bak"
Copy-Item -LiteralPath $databasePath -Destination $backupPath -ErrorAction Stop
# Выполняйте удаление только после успешного копирования и проверки резервного файла.
Get-Item -LiteralPath $backupPath
Remove-Item -LiteralPath $databasePath
```

При следующем запуске сервер создаст пустую базу. Для восстановления остановите сервер и скопируйте резервный файл обратно на место базы, например `Copy-Item -LiteralPath $backupPath -Destination $databasePath`. Базы `*.sqlite3` и их служебные файлы исключены из Git; резервные копии храните отдельно от репозитория. Записи прежней версии, оставшиеся только в памяти процесса, автоматически в SQLite не переносятся.

## Автоматическая проверка

Из корня проекта с установленными зависимостями сервера и RAG запустите весь набор:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -X utf8 -m pytest -q backend/tests
```

В `backend/tests/conftest.py` fixture `client` перед каждым API-тестом подменяет путь базы на новый файл в `tmp_path` и открывает `TestClient` в контекстном менеджере: это запускает инициализацию таблиц. После теста клиент закрывается, а исходный путь базы восстанавливается автоматически. Очищать рабочую базу вручную не нужно.

В `backend/tests/test_api.py` проверяются создание, чтение, список, изменение и удаление документа; отклонение пустого и пробельного `text`; `404` для неизвестных идентификаторов; создание и чтение заявки; отклонение заявки без `question`. Проверяются статусы и поля ответов, а после изменения — повторное чтение через API и отдельное соединение SQLite.

Проверки перезапуска из `backend/tests/test_persistence.py` также входят в запуск pytest. Их можно запустить отдельно без pytest и httpx:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -p test_persistence.py -v
```

Проверки перезапуска используют отдельные временные базы и локальный HTTP-сервер. Они создают документ и заявку, останавливают процесс Uvicorn, запускают новый и сверяют `id` и содержимое. Дополнительно проверяются сохранение PATCH и DELETE после перезапуска, ответы `404` и `422`, строки с кавычками и SQL, откат транзакции, повторная инициализация и безопасный ответ `500` с записью подробностей в журнал. Все тесты используют временные данные и не изменяют учебную базу.
