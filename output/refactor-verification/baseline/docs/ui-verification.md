# Проверка UI → API → SQLite

Проверка выполнена 7 ноября 2026 года по времени пользователя. Интерфейс и API работают только на 127.0.0.1. В SQLite созданы два явно обозначенных учебных документа; из браузера отправлены учебные заявки с именем «Проверка интерфейса».

Итог: два последовательных запуска pytest прошли по 32 теста; SHA256 рабочей базы до и после pytest совпал. Сборка TypeScript/Vite и lint прошли. Прямой SELECT в SQLite (соединение только для чтения) совпал с JSON документа и заявки, созданной из браузера. Рефакторинг не менял формат таблиц и существующие id.

## Что проверено

| Сценарий | Результат |
|---|---|
| Изначально пустой настоящий GET /documents | Показано «Документов пока нет» |
| Создание документов через POST /documents, затем обновление списка | Появились реальные записи с серверными UUID |
| Выбор другого документа | Полный текст и источник совпали с GET /documents/{id} |
| Пустая форма | Ошибки у имени и вопроса, фокус в первом поле |
| Реальный POST из браузера | Получены id и status=new, затем GET подтвердил те же name/question |
| Задержанный POST | Кнопка заблокирована, второй submit не отправил второй POST, раннего подтверждения нет |
| API действительно остановлен | Ошибка загрузки с кнопкой повтора; ошибка отправки сохраняет оба поля и не показывает успех |
| API повторно запущен с той же SQLite-базой | Повтор загрузки восстановил список; документы и заявки доступны с прежними id |
| Страница перезагружена | История браузера восстановила id и перечитала заявку с сервера |
| Серверная ошибка 422 | Сообщение привязано к вопросу; после разблокировки поля фокус переходит в него |
| JSON-ошибка 500, ответ без id, не-JSON ошибка 503 | Понятная ошибка, ввод сохранён, ложного подтверждения нет |
| Клавиатура | Tab/Enter, порядок полей, видимый фокус, отправка формы |
| Размеры | 1440px desktop, 390px и 320px mobile; переполнения по горизонтали нет |

Нормальные сценарии используют настоящий FastAPI и SQLite. В проверочных скриптах задержка сети управляется Playwright, а отдельные ошибочные ответы и повторное пустое состояние задаются явно как тестовые fixture. В коде приложения подстановки ответов и демонстрационного успеха отсутствуют.

## Повторить самостоятельно

Из корня проекта запустите серверы по README, создайте хотя бы один документ через Swagger и откройте браузер Playwright:

```powershell
New-Item -ItemType Directory -Force output/playwright
npx --yes --package @playwright/cli playwright-cli -s=knowledge-desk open http://127.0.0.1:5173 --headed
npx --yes --package @playwright/cli playwright-cli -s=knowledge-desk run-code --filename frontend/scripts/verify-ui.js
npx --yes --package @playwright/cli playwright-cli -s=knowledge-desk run-code --filename frontend/scripts/verify-errors.js
```

verify-ui.js создаёт одну настоящую учебную заявку в выбранной базе. Для сохранения своих данных используйте отдельную учебную базу через KNOWLEDGE_DESK_DB_PATH. Это отличается от pytest, который автоматически изолирует каждый тест временной базой.

Остановите API в его терминале через Ctrl+C и выполните:

```powershell
npx --yes --package @playwright/cli playwright-cli -s=knowledge-desk run-code --filename frontend/scripts/verify-offline.js
```

Снова запустите API с тем же файлом базы и выполните:

```powershell
npx --yes --package @playwright/cli playwright-cli -s=knowledge-desk run-code --filename frontend/scripts/verify-recovery.js
```

Скрипты содержат assert-проверки и возвращают passed/результаты. Снимки сохраняются в output/playwright и исключены из Git. Запускайте команды последовательно, дожидаясь завершения каждой, поскольку они управляют одной вкладкой.

## Дизайн и интерфейс

Референс и токены: [DESIGN.md](../DESIGN.md). Применены frontend-skill, UI Designer, React Best Practices и Web Interface Guidelines. После редизайна проверены native controls, короткие доступные имена, связи ошибок с полями, skip-link, live-результат, длинные строки, перенос id, focus-visible и reduced motion. Это практическая проверка интерфейса; независимого полного WCAG-аудита и нагрузочного тестирования не проводилось.

Сетевые ошибки в консоли браузера при намеренно выключенном API и при тестовых HTTP-ошибках ожидаемы. Предупреждение Starlette об использовании httpx в TestClient остаётся предупреждением зависимости и не мешает текущим серверным тестам.
