# Развёртывание и восстановление Knowledge Desk

Для проверки выбрана отдельная среда Windows x64 с локальным HTTPS, отдельной Python-средой и новой установкой frontend. Supabase обеспечивает Auth, PostgreSQL с pgvector, приватное хранилище PDF и журнал квитанций n8n. Публичный хостинг требует отдельного адреса и сертификата. Для локального стенда дополнительный тариф не понадобился. На 21 ноября 2026 года Supabase Free предлагает 500 МБ базы, 1 ГБ Storage и допускает паузу после недели бездействия. На Free нет автоматических резервных копий. [Условия Supabase](https://supabase.com/pricing) · [Руководство FastAPI](https://fastapi.tiangolo.com/deployment/)

## Запуск локального стенда одной командой

Нужны PowerShell 7.4+, Node.js, OpenSSL и уже настроенные `.venv` и `backend/.env`. OpenSSL может использоваться из Git for Windows. Запустите из корня проекта:

```powershell
.\scripts\start-stand.ps1
```

Скрипт устанавливает отсутствующие зависимости frontend через `npm ci`, собирает интерфейс и запускает сервер на `https://127.0.0.1:8443`. После `HTTP 200` и `status=ready` он открывает приложение в браузере по умолчанию и выводит адрес и полный путь к журналу запросов. Если браузер не открылся, перейдите по напечатанному адресу. Самоподписанный сертификат может вызвать предупреждение для этого локального адреса. Оставьте окно PowerShell открытым. Чтобы остановить сервер, нажмите `Ctrl+C`. Журналы предыдущих запусков сохраняются.

## Установка по точным версиям

Из чистой копии проекта на Windows x64, с Python **3.12.10**, Node **24.11.0** и npm **11.6.1**:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
$env:VITE_API_BASE_URL = '/'
npm --prefix frontend ci
npm --prefix frontend run build
npm --prefix frontend run lint
.\.venv\Scripts\python.exe -X utf8 -m pytest -q backend/tests tests/security
```

Lock-файл сохраняет CPU-сборку PyTorch. Если её загрузка обрывается, скачайте wheel для `cp312-win_amd64` из официального индекса и сверьте SHA-256 по ссылке индекса. Установите wheel в новую среду командой `python -m pip install --no-deps путь-к-wheel`, затем повторите `python -m pip install -r requirements.txt` и `python -m pip check`. В проверке этот способ использовал уже скачанный дистрибутив. [Индекс CPU-сборок PyTorch](https://download.pytorch.org/whl/cpu/torch/)

Для развёртывания скопируйте [.env.example](../.env.example) в серверный `backend/.env`, укажите точный **HTTPS** origin без завершающего слэша и `KNOWLEDGE_DESK_REQUIRE_AUTH=1`. Защищённому режиму нужны PostgreSQL DSN и параметры Supabase Auth из [инструкции](supabase-migration.md). Задайте `KNOWLEDGE_DESK_STATIC_DIR=frontend/dist`, чтобы приложение и API работали с одного origin. Требуются JWT, выданные Supabase Auth, и роль в `knowledge_desk.members`. Сервис проверяет токен через Supabase. [Проверка пользователя Supabase](https://supabase.com/docs/reference/javascript/auth-getuser)

Production-сборка по умолчанию обращается к тому же origin. Если задать `VITE_API_BASE_URL` явно, его значение видно в браузере. Ключ OpenAI, PostgreSQL DSN, пароль Storage и секрет webhook загрузите только в окружение сервера. Для TLS используйте сертификат своего HTTPS-адреса. На стенде применялся временный сертификат для IP 127.0.0.1.

Для первого закрытого пилота запускайте один процесс API. Лимит запросов к модели хранится в памяти процесса, и при нескольких процессах у каждого будет отдельный счётчик. Метрики, восстановление Supabase и проверка внешних интеграций входят в отдельный этап перед запуском пилота.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m uvicorn backend.app.main:app --loop backend.app.postgres:selector_loop --env-file backend/.env --host 127.0.0.1 --port 8443 --ssl-certfile path/to/certificate.pem --ssl-keyfile path/to/private.key --no-access-log
```

На стенде origin и адрес интерфейса равны `https://127.0.0.1:8443`. На сервере за HTTPS-прокси оставьте Uvicorn на приватном интерфейсе, настройте запись и тайм-ауты на прокси и разрешите передавать forwarded-заголовки только от доверенного прокси. Ограничьте тело запроса на прокси до 10 МиБ с учётом используемых маршрутов.

## Данные, готовность и границы доступа

| Данные | Постоянное место |
|---|---|
| Документы, заявки, черновики и квитанции | PostgreSQL, схема `knowledge_desk` |
| Фрагменты и embeddings | PostgreSQL, `rag_chunks`. Профиль задаёт `KNOWLEDGE_DESK_CHUNK_SIZE` |
| PDF и сканы | Приватный бакет `knowledge-desk-originals` |
| Веса E5 | `KNOWLEDGE_DESK_EMBEDDING_CACHE` или `data/.model-cache`. Сохраните кэш на постоянном диске |
| Локальная разработка | `KNOWLEDGE_DESK_DB_PATH`, `KNOWLEDGE_DESK_INDEX` и соседняя с SQLite коллекция загрузок. Запуск на loopback |

`GET /health` возвращает HTTP 200 с тремя короткими статусами при доступных базе и индексе. При сбое после старта возвращает HTTP 503 и `not_ready`. Пробы занимают до 3 секунд и не запускают поиск, эмбеддинг или генерацию. Здоровье проверяет доступность индекса, даже если коллекция ещё пуста. Готовность самой модели лучше проверять отдельным вопросом с вымышленными данными.

| Проверка | Конфигурация |
|---|---|
| Origin, вход | Точный HTTPS origin, HttpOnly/Secure/SameSite=Strict. Роль и владелец определяются на сервере |
| Модель | До 15 секунд, автоматических повторов нет. Резюме принимает до 4000 символов, поиск до 1200 |
| Auth, инструмент, webhook | HTTP-клиент Supabase Auth 8 секунд. Инструмент до 3 секунд на попытку. Webhook до 5 секунд без автоматического повтора |
| Импорт | 64 КиБ для текста, 10 МиБ для PDF/Word, до 256 КиБ извлечённого текста |
| Логи | Uvicorn с `--no-access-log`. Этапы содержат шаблоны маршрутов, серверные ID, числовые метрики и безопасные коды |

Повтор доставки и сверка квитанции описаны в [инструкции n8n](n8n-delivery.md). Перед публикацией учитывайте процессные лимиты модели, отдельное управление секретами, мониторинг и резервное копирование PostgreSQL и Storage. Заранее проверьте восстановление на тестовых данных. [Ограничения RAG](rag-limitations.md)

## Проверенный запуск 21 ноября 2026 года

В чистом окружении установлены все 143 зафиксированные версии Python. `pip check` не нашёл проблем. После `npm ci` сборка и линтер прошли. Полный pytest в новой среде дал **187 тестов и 8 подтестов**. Оставшиеся 66 предупреждений относятся к устаревшей конфигурации embedding-функции Chroma.

В отдельной копии приложения через Playwright выполнен вход по HTTPS с двумя тестовыми аккаунтами. Вопрос вернул факт о вымышленном архиве и цитату из загруженного документа. После подтверждения консультации тестовый n8n вернул квитанцию, а карточка показала «Доставка подтверждена». Затем сервер запущен заново из чистого Python-окружения. По тем же ID открылись документ, цитата, черновик, заявка и квитанция. Повтор подтверждения вернул ту же квитанцию.

| Запрос | Результат |
|---|---:|
| `POST /requests` без сессии | 401 |
| `POST /requests` с чужим Origin | 403 |
| `POST /documents` от читателя | 403 |
| `GET /documents/{id}` и `GET /ask/sources/{chunk_id}` от другого пользователя | 404 |
| `POST /consultations/{id}/confirm` от другого пользователя | 404 |
| `GET /requests/{id}`, `GET /requests/{id}/delivery` и `POST /requests/{id}/delivery/retry` от другого пользователя | 404 |

На рабочем стенде `/health` вернул `{"status":"ready","database":"ok","index":"ok"}`. На временном стенде с отсутствующей коллекцией маршрут вернул 503. Проверены атрибуты сессионного cookie, отсутствие значений серверных секретов в исходниках, сборке и журналах стенда и закрытый доступ к `/backend/.env`. [Результаты, trace ID и контрольные суммы проверенной версии](../data/eval/deployment-evidence.json) · [Диагностика](diagnostics.md)

## Проверка на отдельном Supabase

Для проверки используйте локальный проект Supabase CLI с отдельным `project_id` и портами API **55321** и PostgreSQL **55322**. Скопируйте `supabase/migrations/` в его папку `supabase/` и запустите локальный стек. Соберите frontend и выполните из корня Knowledge Desk:

```powershell
supabase --workdir $smokeProject status --output json |
    .\.venv\Scripts\python.exe -X utf8 -m scripts.verify_supabase_local
```

`$smokeProject` указывает на папку проекта проверки. Скрипт создаёт вымышленных пользователей и записи в этой локальной базе. Он проверяет миграции, готовность защищённого приложения, доступ к PDF и pgvector, выдачу справки и повтор доставки. Вектор модели, почта и внешний webhook подменены в процессе проверки.

## Восстановление

Поднимите предыдущую проверенную копию исходников и её lock-файлы по тем же командам. Восстановите серверные секреты из своего хранилища и сначала проверьте `/health` и аккаунт с тестовой ролью. Для локальной учебной базы остановите пишущий процесс, сохраните текущий файл и проверьте резервную SQLite через `PRAGMA integrity_check` перед заменой. Для Supabase восстановление базы и бакета проверяйте отдельно от отката сервера. Сохраняйте прежние ID документов, заявок и событий при переносе данных.
