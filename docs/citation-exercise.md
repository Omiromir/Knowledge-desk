# Упражнение с цитатой

Пробел из B27. Я смешал две проверки: можно ли по `chunk_id` найти исходный отрывок и подтверждает ли этот отрывок конкретную фразу в ответе. Хочу уметь объяснить, почему проверка идентификатора проходит, хотя вывод о пароле ошибочен.

Первая попытка: положить один отрывок в словарь и читать через `fragments[chunk_id]`. С `login-001` получил текст. С `login-999` получил `KeyError` вместо понятного результата. Возник вопрос, как отличить отсутствующий ID без обработки исключения. После попытки проверил точный раздел [Python 3.12 про `dict.get`](https://docs.python.org/3.12/library/stdtypes.html#dict.get).

В [готовом примере](examples/citation_lookup.py) `resolve_citation` получает ID и ищет его среди заранее переданных фрагментов. `get` возвращает текст или `None`. При `None` функция возвращает `unknown_chunk_id`. В остальных случаях она возвращает ID и текст из словаря. Блок запуска вызывает функцию дважды, сравнивает оба результата с ожидаемыми и печатает их.

```powershell
.\.venv\Scripts\python.exe -X utf8 docs/examples/citation_lookup.py
```

```text
{'chunk_id': 'login-001', 'text': 'Пароли в заявку в поддержку не прикладывают.'}
{'error': 'unknown_chunk_id'}
```

Теперь могу разделить проверки. ID позволяет открыть именно тот отрывок, который видел ответчик. Смысл приходится проверять отдельно: фраза про заявку говорит, что делать при обращении в поддержку. Про вход в систему она ничего не сообщает. Остаётся вопрос, как надёжно обнаруживать такие подмены смысла во всех формулировках. Для него нужны независимые проверки смысла и конкретные отрицательные примеры.
