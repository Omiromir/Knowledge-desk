# Решение по поиску на индексе 600/50

**Сохранить векторный поиск.** В контроле на 600/50 все ожидаемые документы вошли в top‑5 для 15 вопросов с ответом. Два оставшихся отклонения связаны с использованием уже переданных фрагментов.

| Случай | Место подтверждающего фрагмента | Наблюдение |
|---|---|---|
| R07 | `consult-reschedule` № 3, расстояние 0,1462 | Порог 12 часов и снятие встречи присутствуют в переданном тексте. Лишнее утверждение об отказе принять заявку появилось при генерации. |
| R15 | `completion-certificate` № 1, 0,0977, и `lesson-recordings` № 3, 0,1494 | Оба источника переданы модели. Ответ расширил условие о незакрытых заданиях до общего правила. |

Для [восьми вопросов](../data/eval/retrieval-top20.json) с неудачей хотя бы в одном из прогонов повторён поиск до top‑20 на 600/50. В каждом вопросе подтверждающие фрагменты оказались среди первых пяти. Для R12 расписание на месте 1 и цена на месте 4, для R13 подготовка к консультации на месте 1. На этих данных потеря точных слов и размещение нужного факта на местах 6–20 не воспроизводятся. Вывод относится к вопросам этого корпуса.

```powershell
.\.venv\Scripts\python.exe -X utf8 retrieve.py --index data/orbita-600-v1.chroma --chunk-size 600 --top-k 20 --question 'Когда начинается занятие по аналитике в субботу и сколько стоит этот курс?'
```

Контрольный поиск на CPU занял 117,42 мс по p95, полный ответ 3,117 с по p95. Индекс занимает 708 772 байта. Дополнительных запросов к модели для этой диагностики было 0. Замер дополнительной задержки hybrid search или reranking применим при воспроизводимом дефекте. Команды ручного включения индекса 600/50 и возврата на 400/50 описаны в [отчёте о разбиении](chunking-experiment.md#воспроизведение-и-ручное-переключение).
