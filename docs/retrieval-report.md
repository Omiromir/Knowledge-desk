# Учебный корпус «Орбита» и локальный поиск

## 1. Корпус

В [манифесте](../data/manifest.json) 20 Markdown-документов в UTF‑8, по четыре на тему. Темы охватывают курсы, расписание, запись и оплату, консультации и правила обучения. Каждый документ содержит стабильный `doc_id`, название, путь к исходному тексту, дату версии и основание использования. «Орбита» и все её условия вымышлены. Сторонние тексты в корпус не вошли.

Проверены строгая декодировка UTF‑8, читаемая кириллица, непустой текст, уникальные ID и пути, а также SHA‑256 нормализованных тел документов. Тексты проверены на реальные контактные данные и секреты. **Удалённых дубликатов нет.** Единственный рассмотренный файл вне корпуса — [прежний FAQ](../data/faq.json). Он оставлен на месте и исключён из манифеста, поскольку относится к другому учебному сценарию, включая правила о возрасте и документах при записи.

Импорт в API проверен с временной SQLite-базой. Первый прогон создал 20 записей, второй оставил все 20 с прежними UUID. Чтобы добавить их в свой работающий FastAPI, запустите из корня проекта:

```powershell
.\.venv\Scripts\python.exe -X utf8 import_corpus.py
```

Импорт сопоставляет записи по стабильному пути источника. `doc_id` остаётся идентификатором корпуса, а API выдаёт UUID записи. Скрипт выводит соответствие обоих идентификаторов. Рабочая база в ходе проверки импорта не менялась.

## 2. Индекс

Одна модель `intfloat/multilingual-e5-small` с ревизией `614241f622f53c4eeff9890bdc4f31cfecc418b3`. Sentence Transformers вычисляет нормализованные 384-мерные векторы на CPU. Фрагменты получают префикс `passage:`, вопросы — `query:`. Коллекция `knowledge-desk-orbita` в `data/chroma` получает готовые векторы, тексты и метаданные. Встроенная функция эмбеддингов Chroma отключена. [Карточка модели и правила префиксов](https://huggingface.co/intfloat/multilingual-e5-small)

Разбиение сохраняет абзацы там, где граница достаточно близка к целевым 400 символам, и подбирает начало следующего окна около 50 символов до конца предыдущего. В текущем корпусе получилось 41 окно. Длина составляет от 152 до 400 символов, медиана — 357. Фактическое перекрытие составляет от 39 до 50 символов, медиана — 45. `chunk_id` включает отпечаток `doc_id`, даты версии, нормализованного текста, настроек и границ окна. Смещения `start` и `end` относятся к нормализованному тексту исходника.

### Команды Windows

```powershell
.\.venv\Scripts\python.exe -m pip install --index-url https://download.pytorch.org/whl/cpu torch==2.8.0
.\.venv\Scripts\python.exe -m pip install -r requirements-rag.txt
.\.venv\Scripts\python.exe -X utf8 ingest.py
.\.venv\Scripts\python.exe -X utf8 ingest.py
.\.venv\Scripts\python.exe -X utf8 retrieve.py --output data/retrieval-results.json
```

При первой установке и загрузке модели нужен интернет. После загрузки файлов модели `HF_HUB_OFFLINE=1` позволяет запустить поиск без доступа к Hugging Face. В PowerShell задайте `$env:HF_HUB_OFFLINE = '1'` перед командой поиска.

Первый запуск записал 41 фрагмент. Второй оставил 41, записал 0 и удалил 0. Проверка прочитала все 41 вектор из Chroma. У каждого 384 координаты, норма близка к единице, а текст совпадает с указанным диапазоном в документе.

## 3. Проверка поиска

Ожидаемые источники записаны вручную в [наборе вопросов](../data/retrieval-cases.json). Попадание засчитывается, если хотя бы один ожидаемый `doc_id` есть среди пяти ближайших фрагментов. Один документ может встречаться несколько раз. В Chroma используется косинусное расстояние `1 − cosine_similarity`. Чем меньше значение, тем ближе векторы. Это расстояние, поэтому оно не показывает вероятность правильного ответа. [Метрика Chroma](https://docs.trychroma.com/docs/collections/configure)

**Hit@5 = 10/10 = 1,00.** Ожидаемый источник оказался первым в восьми вопросах. [Полные результаты](../data/retrieval-results.json) содержат все 50 фрагментов, их `chunk_id`, `doc_id`, тексты, исходники, диапазоны и расстояния. Поиск выполнен в офлайн-режиме Hugging Face без ключа OpenAI. Все 50 текстов сверены со своими диапазонами. Генерация ответа в проверку не входит.

### Два слабых результата

- **Q06, портфолио после одного курса.** Первыми оказались фрагменты про выбор курса и записи занятий. В вопросе «обсудить портфолио» и «встреча» задают тему косвенно. Материал присутствует целиком в третьем фрагменте: условия допуска и 40 минут помещаются в одном окне. Здесь проблема в ранжировании запроса.
- **Q07, перенос менее чем за полсуток.** Сначала найден общий фрагмент про согласование консультации. На втором месте правильный документ, но этот фрагмент начинается с конца абзаца и не содержит правила про 12 часов. Полное правило, включая снятие встречи из календаря при позднем обращении, находится на третьем месте. Здесь сыграли и косвенная формулировка вопроса, и граница окна. Hit@5 по источнику засчитывает вопрос, хотя для ответа нужен соседний фрагмент.
