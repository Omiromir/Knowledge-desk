# Проверки CI и откат

Workflow [Checks](../.github/workflows/checks.yml) запускается на push и pull request. Backend использует Windows и версии из `.python-version` и `requirements.txt`. Frontend использует `.node-version`, `npm ci` и production build. Итоговый check **Ready to merge** успешен только после успешных backend и frontend jobs. XML тестов и JSON mock-eval скачиваются из раздела Artifacts. Платные ключи в workflow не передаются.

Для выпуска выбирайте полный SHA с успешным **Ready to merge**. Если репозиторий использует правила защиты веток, этот check должен быть обязательным для основной ветки. Намеренные ошибки для репетиции размещайте в отдельной ветке, которая не связана с развёртыванием.

## Откат кода

1. Найдите последний проверенный SHA в истории Actions и сверьте commit в manifest его mock-eval.
2. Проверьте, что эта версия совместима с текущей схемой данных. Сохраните текущие логи и отчёт.
3. Отмените отдельное изменение через `git revert <SHA_изменения>` в отдельной ветке. Для возврата работающего экземпляра можно собрать чистую копию проверенного SHA.
4. Дождитесь зелёных **Checks**, проверьте `/health`, права A/B и повтор доставки с прежним `event_id`. [Сборка и запуск](deployment.md)

## Если менялась база

Откат приложения и откат схемы выполняются отдельно. Сначала сохраните резервную копию данных, индекса, Storage и журнала квитанций, затем проверьте восстановление на изолированной копии. Для несовместимой схемы согласуйте порядок шагов и проверьте исправляющую миграцию, сохраняющую ID, связи и квитанции. Для потерянных данных требуется восстанавливаемая копия или специально подготовленная миграция данных.
